About / Why Klondike?

Years ago, a one-time hand-built list tried to catalog the wider Mycroft/OVOS skill ecosystem - useful at the time, but a snapshot, not something that stayed current, and it's gone now. Today's OVOS ecosystem is smaller than that era's, but still genuinely hard to see all at once: skills, plugins, and tools live scattered across dozens of different GitHub accounts and orgs, with no single place that reliably shows what actually exists.

Klondike exists to answer that continuously, not as a one-time count - discovered automatically via code, topic, and repo-name search across all of GitHub, checked against PyPI, GitHub releases, and OVOS's own upcoming Skill Store (not yet officially launched) every few hours.

What you see comes from three sources, and each is shown as such:

  • What we found: badges such as Looks Complete or Works Offline describe the repo, its PyPI package and its releases. They say nothing about whether it works.
  • What we tested: every Looks Complete skill and pipeline plugin is installed and started on OVOS's release channels (testing, alpha, stable), and a skill's own sentences are sent to it with the OVOS installer's default skills loaded. The result is the small channel label on the card.
  • What people reported: a maintainer's test on a real device, and reports from users' own setups. They are shown next to our result, never as it.

See release notes for what's changed, and suggest an idea or improvement if something's missing.

What do the labels and badges mean?

What we found

Looks Complete
Has a proper skill.json/entry-point declaration, is published on PyPI, and has a GitHub release - OR is already listed in OVOS's own upcoming Skill Store (not yet officially launched; a stronger signal on its own, since that store doesn't require PyPI or a release either). Not the same as confirmed working: see What we tested below.
Incomplete
Has a skill.json, but is missing a PyPI release and/or a GitHub release.
Inferred, Unconfirmed
No skill.json found. The repo tags itself as OVOS-related and its code shows real signs of being a skill, but everything shown is guessed from the repo's own description/topics - treat it as a lead, not a confirmed listing.
Works Offline
The skill's own description states it needs no internet connection.
LAN Only
Uses local networking (device discovery, mDNS, etc) but not the internet - a different thing from "Works Offline" (no networking at all).
Offline + Online
Works offline, with an optional online component (e.g. a fallback for content the offline data doesn't cover).
Needs Internet (WAN)
Fetches content from the internet to function.
OVOS Store
Also listed in OVOS's own upcoming Skill Store (not yet officially launched).
API key
Requires an API key or similar credential to configure.
Not on PyPI / No release / No license
Exactly what it says - shown as a plain fact, not a reason to exclude the skill.

Want your repo listed or classified correctly?

The short version:

  • Get found: add the ovos or openvoiceos GitHub topic to the repo.
  • Get classified: a skill.json for a skill, a namespaced entry point for a plugin.
  • Reach Looks Complete: publish on PyPI and make a GitHub release (or get into OVOS's Skill Store).
  • Get tested: Looks Complete skills are tested automatically on every channel; add test/end2end/golden_utterances_<lang>.jsonl to reach level 3, or publish your own report from a real device.

The full guide for maintainers explains each step, what the tests do, and the README badge.
